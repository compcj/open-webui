## 修复与复核记录

- 合并重构后修复了 Legacy 来源变量和 V2 续接模型身份、共享导入私有 metadata、断线互动重投/答复鉴权，以及加密 Relay 接收侧的实时授权。
- 临时结果先持久化执行记录，再原子发布完整原文及可信来源；待发布结果阻止新请求、转存和回收。任务预留失败逐个回收，执行者完成后才确认停止，未知工具结果不能当作完成。
- 手动压缩保留临时请求 metadata，直连 RPC 用一次性 claim 校验 scope/task/reply/model/socket generation；续写复用回复 ID 时，只接受状态中唯一活动的后继任务，拒绝旧任务迟到事件。
- 转存按服务端完整原文快照构造内容，幂等重试返回同一聊天；保存和导出剥离派生身份，同时保留调用配对、原始 provider function、冻结引用和原生签名。
- 已完成任务和执行控制记录曾累计占用 32/128 条控制额度，可能在长对话中拒绝新轮次。现在只退休执行者已确认完成且结果全部发布的任务；任务 ID 摘要计入数据配额，原文、已采用版本、账目和未知执行均保留。真实双 worker 连续 40 轮验证与 Memory/Redis 五模型并发回归覆盖此修复。
- 标准镜像实测发现浮动 torchaudio 2.11 与 torch 2.9.1 ABI 不兼容，固定 torch 2.9.1 / torchvision 0.24.1 / torchaudio 2.9.1，并约束后续 requirements 安装。
- 全量测试曾发现旧 AST 夹具边界失配及 checkpoint fixture 复用前测缓存 Base。修复夹具后保留真实 SQLite、来源失效、模型隔离、并发 CAS 和迁移断言；最终整套结果以上表为准，没有把过程中的失败运行写成通过。

## 验证主机故障与恢复边界

早期并行容器导出耗尽 Windows C 盘，原 WSL 的 ext4 日志中止并进入只读。三次标准构建未成功导出，途中一轮 Python 3.11 全量检查也被数据库故障中断；这些运行均不计为通过。清理仅限本任务已忽略、可再生成的 build/.svelte-kit，保留源码、依赖、Git 和日志。

最终构建和真实服务迁到 D 盘的独立任务 WSL，并使用单一构建、独立 Redis 7.0.15/PostgreSQL 16.15 后重新完成上述检查。原环境随后产生的约 5 GB 崩溃诊断完整转存到任务忽略目录。经用户明确允许，已停止并尝试重新启动原 Ubuntu；启动仍返回 `Wsl/Service/CreateInstance/E_FAIL`，原发行版未恢复。按约定未运行 fsck、卸载或重建原发行版，也未改变其文件。新验收环境未受这次重启影响。

该主机问题仍需另行处理；它不被本报告的新环境测试结果掩盖，也不属于已完成的代码修复。

## 明确限制与升级方式

实际应用使用本地合成模型响应；外部 OpenAI/Gemini/Anthropic 服务、真实 OAuth 提供商、生产 CA/HA failover、GPU/ARM 镜像和混合版本滚动升级没有冒称验收通过。标准 CPU 镜像、本地音频模型及表列真实 Redis/PostgreSQL/HTTP/Socket.IO 场景有独立证据。

临时对话只在当前页面内存保留，不增加刷新后完整历史恢复。Redis 缓存服从部署现有 AOF/RDB、复制及备份策略，不能描述为“永不落盘”。关闭或过期不等于工具已经结束；不确定执行保留拒绝与重试状态，不能靠删除缓存或创建新 scope 重做工具。

部署应先排空旧 worker，再协调切换。新 Redis reader 可读旧快照，旧 reader 不识别新格式；没有证明混合版本滚动安全。回滚恢复升级前数据库、上传、配置和镜像整套备份，不只切镜像或修改 Alembic stamp。升级不主动开启 V2、Apps、Tool Search、Realtime 或加密频道。

产品理由和旧决策替代关系见[决策记录](v0.12.4-decisions.md)，完整接口、缓存配置、状态机和保存规则见[临时 V2 指南](../temporary-context-v2.md)，后续检查入口见[DEVELOPMENT](../DEVELOPMENT.md#v0124-integration-and-temporary-v2-verification)。
