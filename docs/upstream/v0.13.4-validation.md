## 手动上游回归

固定的外部[官方测试提交](https://github.com/open-webui/tests/tree/66c2ededb9ab48dc6eb89556fb16780f784e6591)是 `66c2ededb9ab48dc6eb89556fb16780f784e6591`。在该仓库目录运行 pytest，`OPEN_WEBUI_SOURCE_DIR` 指向这个候选工作树的 `backend`，`OPEN_WEBUI_BUILD_DIR` 指向其 `build`。每次运行创建新的临时数据目录并执行迁移。

进入官方测试仓库后，执行 `python -m pytest unit/chat unit/config unit/deps unit/footprint unit/frontend unit/imports unit/migrations unit/models unit/pipelines unit/retrieval unit/routers unit/tools -q`。Windows 结果为 **286 项通过、24 项跳过、2 项失败**。另行单跑文档提取、网页加载、Oracle 驱动和路由装配的 21 项全部通过。

- `test_every_router_imports_without_a_cycle` 在 Windows 原测试的 8 路并发下触发子进程 180 秒上限。将同一固定测试原样放入 Linux standard 候选镜像后，40 个路由全部完成冷启动，**1 项通过，110.55 秒**。每个路由使用独立 SQLite，保持官方并发和超时。
- `test_every_process_lifetime_container_has_a_recorded_bound` 的静态白名单缺少两项 fork 状态。`INTERACTION_AUTH_PENDING` 在认证超时或完成后通过 `finally` 清理。`_pending_completions` 在临时上下文结果发布和执行确认后移除，暂时失败时保留以重试。官方测试固定在原提交，故这一项仍为差异。[会话确认实现](../../backend/open_webui/socket/main.py) · [临时执行收尾](../../backend/open_webui/utils/temporary_context_runtime.py)

## 真实环境与发布检查

- 两种 Linux/amd64 镜像均经过实际构建和离线启动。standard 加载 torch、torchvision、torchaudio 的 CPU wheel 并完成张量运算。slim 在这三个包都未安装的情况下启动。均使用临时 SQLite 请求 `/health`。
- 浏览器使用 Edge 158.0.4370.33 登录候选前端，进入聊天和管理设置，将 Agent Auto 从默认 WebUI 审查切换到原生审查，保存、刷新并恢复默认。浏览器没有产生 pageerror。
- 独立 Open Terminal 0.17.7 完成真实文件写入、读回和第二账号拒绝。实际 Terminals orchestrator 0.4.1 固定在 `779e53e9c0c90406a5d981156096ca43391ba840`。认证模板目录、模板创建、父连接 write 委派、模板 read 共享与撤权均经 HTTP 核验。
- 以 Starlette 的路径匹配规则和注册顺序检查 692 个官方 method/path 与候选的 714 个入口。40 个官方路由挂载全部可达，包括 6 个视频入口和 15 个模板管理入口。视频生成和可视化工具的注册守卫与官方一致。
- `uv lock --check` 验证 333 个已解析包。发布端点的四项后端回归覆盖了 fork 或上游单独读取失败、关闭在线检查及合法的发布标签。
- `/api/version`、Hatch wheel 元数据及 OCI `org.opencontainers.image.version` 均返回 `0.13.4+f1`。官方 `docker/metadata-action` 的两个工作流作业实际输出 exact、系列、Git SHA 三种镜像标签，覆盖 main、cuda、cuda126、ollama、slim。CUDA、Ollama 及 ARM 镜像只核验了发布元数据。
- `bash scripts/check-workflows.sh` 通过。Ruff 按仓库格式和 F 规则检查 Python 源文件。Prettier 和 `npm run i18n:parse` 使用仓库配置，并验证所有语言的占位符。
