## 实施期间确认的协议边界

以下是用户在审查真实上游协议后明确确认的补充决策，优先于原计划中相应的宽泛表述。

| 决策                | 确认结果                               | 实际边界                                                                                                                |
| ------------------- | -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| D07a 终端 Cookie    | 保留终端服务端 Cookie jar              | 页面仍不能使用 DOM Cookie/localStorage；不宣称终端到目标网站的请求无 Cookie。需要完整浏览器语义时使用 Chrome。          |
| D07b 端口 WebSocket | 沿用上游浏览器网络权限，允许内部重定向 | 票据授权端口及初始 WS 目标仍检查；Open Terminal 内部可跟随目标重定向，不宣称完整网络端口隔离。                          |
| D06a Agent 强制停止 | 允许强制终止并标记可能缺失的尾部       | 保存服务端已收到并可保留的原文；强制停止可能删除终端尚未传回的缓冲。仅远端确认终止后解锁，404、超时、丢失响应仍未确认。 |

D06a 的原因是当前 Open Terminal 的通用强制停止只有破坏性 DELETE：先删除会话，再终止进程，
没有完成 tombstone 或可验证最终输出游标。不能同时保证任意进程强制退出、所有远端尾部输出和
丢失 DELETE 响应后的确定性恢复。WebUI 不通过重新发起 Agent 请求恢复输出，也不把无记录当完成。
准确的实现、故障状态和容量说明见[Agent 指南](../tether-agents.md)。

## 独立复核后的兼容修正

在 `660571e6ceec7a0af8551e90378a0ea39c71380b` 上独立复核后，用户授权修复五项集成回归。
这些修正落实已有权限、签名和临时上下文合同，不改变上述产品决策：

- 原生 Agent 在接受审批和实际发送新输入时重查终端访问，覆盖审批等待期间撤权及重连输入；
  保留原终端身份、已接收原文和停止确认流程。
- 文本工具恢复遇到受保护的 Anthropic/Gemini 原生回复时保留原文和签名，不将其改写为推断工具调用。
- 主聊天初始化临时 V2 工作目录时传入该 scope 的身份与 epoch。
- SideChat 向后代提供自己的临时上下文，使原始工具结果从正确的临时接口读取。
- SideChat 在 off/legacy 临时历史投影中保留 assistant 的模型标识，维持同模型原生签名回放。

修复的回归与重新验证结果见[验证记录](v0.13.3-validation.md#独立复核修复与重新验证)。

## 配置与兼容

- 新增 `ENABLE_TETHER` → `tether.enable`，默认 false；旧客户端省略字段时保留值。全局 WebSocket
  关闭时也不提供 Tether。手工个人连接仍受 `direct.integrations.enable` 控制，管理员服务器连接独立。
- 新增 `TERMINAL_PREVIEW_BASE_URL` → `terminal.preview.base_url`，默认空。主站与预览必须不同主机名；
  生产 HTTPS，明确回环开发例外。旧预览 Host 永久保留为预览专用，公开配置重置不撤销该保护。
- 预览票据 300 秒、活动标签每 60 秒续权，绑定用户、登录、终端、目标与保存/临时上下文。无 Redis
  仅支持单 worker/实例，Redis 故障不回退内存。票据及原始终端凭据不进入布局、聊天或日志。
- 浏览器标签优先复用自己的终端会话；端口仍来自 actor-visible `/ports`。仅提供端口的独立 API 客户端
  使用受持久化占位保护的会话创建；丢失响应时不盲目重复创建。详见[预览指南](../terminal-preview.md)。
- 升级不自动开启 V2、知识写入、技能自动发现或 Auto 审批。已保存显式设置和原始上传保持原状。

新旧 reader 混合滚动升级。显式设置无需重配，知识索引不自动重建。先验证唯一 head 与数据保留，
再开放任务；升级失败恢复同一时间点的整套备份，不仅回退应用镜像或任意降级数据库 head。
