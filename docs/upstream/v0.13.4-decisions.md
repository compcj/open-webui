## 已确认的 17 项选择

| 编号 | 场景                     | 决策及其对用户的影响                                                                                                                                                                                     |
| ---- | ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | 个人连接                 | 个人模型 Direct Connections、个人工具/终端 Direct Integrations 与默认关闭的管理员 Tether 开关分别控制。Direct API Chat 另有独立授权。关闭个人连接会保留已存设置。                                        |
| 2    | 图像连接                 | 采用上游按连接授权、按模型选择的生成和编辑目录。旧命名配置迁入目录并保留稳定 `engine_id`。一组配置可引用不同连接，继承默认编辑器或明确禁用编辑。生成、编辑的工具说明独立保存。执行时重查所选能力的权限。 |
| 3    | Agent 原生分支与重新生成 | 原回复作者在同一个已保存聊天中可使用经过校验的检查点。分享、复制与侧聊只带可见历史。原生会话身份绑定原作者、聊天、终端和目录。                                                                           |
| 4    | 共享聊天与终端           | 聊天写权限允许保存聊天选择。每次针对终端的操作分别检查当前操作者的个人或群组授权。聊天协作者可以在看得到该聊天时仍然没有该终端的使用权限。                                                               |
| 5    | 托管终端升级             | 管理员手动将旧连接重新绑定到 Terminals orchestrator 0.4.0 或更新版本。旧地址和凭据保留供核对。实例启动和停止要求 0.4.1 或更新版本。                                                                      |
| 6    | 附件投递                 | 普通终端和 Tether 默认继续上传到 WebUI。显式为对应连接选择 filesystem 后，本次发送的附件才会复制到该终端。                                                                                               |
| 7    | 回复中追加指示           | 已保存聊天的所有者可向自己正在运行的单模型普通回复追加指示。队列绑定原回复、分支和任务，等待结果完整发布和执行者确认结束。临时聊天、原生 Agent 和多模型比较使用各自既有的交互方式。                      |
| 8    | 原生 Agent Auto          | 由 WebUI 管理是默认选择。独立的原生 Agent Auto 设置允许支持的提供方自行决定常规操作。实际升级审批交给当前回复作者。普通 WebUI 工具使用独立的审批模式。                                                   |
| 9    | Agent 基础模型切换       | 同一已安装 Agent 支持目标基础模型、用户仍有访问权限且执行绑定完全匹配时可复用会话。变更终端、目录、作者或聊天需要新的执行绑定。                                                                          |
| 10   | 旧会话恢复               | 有签名的旧会话只有在能证明前次执行已结算时才可恢复。已结算但缺少足够绑定证明时用可见历史创建新会话。仍有未结算执行时阻止下一轮。                                                                         |
| 11   | 更新提示                 | 在界面分别显示可安装的 fork 发布与上游发布及其链接。同一上游版本的 `f` 修订按数字比较，一方查询故障不阻塞另一方。                                                                                        |
| 12   | 发布标识                 | 应用、包及 OCI 版本标签使用 `0.13.4+f1`，Git 使用 `v0.13.4+f1`。GHCR 使用精确修订标签 `0.13.4-f1` 及系列标签 `0.13.4`，与变体后缀组合。                                                                  |
| 13   | 终端模板/实例管理        | 可用显式 write grant 向用户或组委派模板管理及其他用户实例的管理。检查操作者、操作目标和当前连接的 grant，读取和聊天写权限单独判断。                                                                      |
| 14   | 原生 Agent 附件          | 仅允许为本次发出的消息投递其明确附加的文件。历史附件、复制来的引用和其他人的附件不自动传入 Agent。                                                                                                       |
| 15   | Tether 模型重名          | 保留已有的模型路由。每个发生冲突的 Tether 模型都带来源标识，设备所有者可逐一选择。重新发现、重排和断线后不得静默改投另一台设备。                                                                         |
| 16   | CI 与外部回归            | 保留 fork 的 CI、镜像与发布工作流。对候选代码手动运行固定提交 `66c2ededb9ab48dc6eb89556fb16780f784e6591` 的官方外部回归。实际范围、结果和环境限制以本版验证记录为准。                                    |
| 17   | 旧 Agent ID              | 固定模型、默认模型和自动化中的旧 ID 仅在当前用户有且只有一个在线、可访问的匹配项时迁移。缺失、重名或无权限时保留原值，供用户手动重新绑定。                                                               |

上游本版新增按连接管理的图像/视频模型、终端模板和实例、Agent 交互与可视化工具。分支保留原生模型传输、V2 预算、知识写入和审批回放的既有约束。D04a 继续只把由服务端识别的自动上下文投影为 Chat Completions 系统内容，保留真实工具调用和冻结快照。[D04a 技术决策](v0.13.3-private-context-followup.md) [v0.13.3 决策](v0.13.3-decisions.md)

## 数据、升级与回滚

1. 排空正在运行的聊天、审批和原生 Agent 任务，确认执行结束并保存已接收的原文。备份数据库、上传目录、配置、凭据和正在部署的镜像标识。
2. 协调替换所有 worker。图像配置首次读取时，将原单引擎的默认模型以及旧的命名配置写入连接和配对目录。已迁移的空目录保留空值。核对生成/编辑默认值、每个连接的授权、工作流和配对。
3. 管理员逐一确认需要重新绑定的 orchestrator 连接、模板和权限。核对旧 Agent ID 的可用匹配项。用两个不同授权的账户验证共享聊天的终端、文件、预览和实例管理边界。
4. 回滚时恢复整套升级前备份与镜像。执行记录、已选工具结果及终端重绑定在同一时点恢复。原生可续跑身份始终限于原始聊天。
