## 兼容影响和明确边界

- 从未开启 Direct Integrations 的部署，其已存个人连接升级后不再参与聊天；管理员开启后可恢复。不能静默迁移为开启。
- 立即加载技能会增加首轮上下文并触发实际加载时的 OpenClaw 准备；提供 lazy 开关，但升级不将其默认为 true。自动发现不是资源授权。
- Access 修改即时保存，取消资源编辑不撤回该修改；普通内容更新不能作为旧分享 API 使用。
- 临时 V2 需要新客户端传递服务端 scope 和完整来源身份。缺失时明确要求刷新；不静默绕过预算或回退 Legacy。
- 保留知识写入默认关闭、附件范围、实时 ACL、原始上传及索引部分完成；Notes 精确编辑不扩大知识写权限。
- 新 Redis reader 兼容旧 hash，旧 reader 不识别新 key；采用排空和协调切换，不假定混合版本滚动安全。

## 临时 V2 已批准技术边界

独立 `/api/v1/temporary-contexts` 提供创建、sync、lease、state、context-usage、compact、原文分页和关闭；生成请求携带 `temporary_context: {id, epoch, revision, branch_id}`。服务端用户绑定和 epoch 与 socket 路由分离，每个模型／分支／回复独立，客户端不能签发 checkpoint、selection 或执行证明。

配置 Redis 时使用共享 CAS store，Redis 故障返回 503；无 Redis 仅支持单实例单 worker 有界内存。默认空闲 30 分钟、断线宽限 5 分钟、最长 24 小时，页面每分钟续租；每 context 64 MiB、每用户 128 MiB／最多 4 contexts、每 store 512 MiB，支持服务端配置。

配额含原文与派生数据，媒体保留引用；不截断原文、不淘汰活动执行或已采用版本。工具先写 started，再执行，成功记录 resolved，结果存储失败／无法确定记录 uncertain，不借缓存缺失重执行。关闭／过期先隔离 epoch 并停止，确认执行者完成才清理；TTL、租约、通知均不是完成证明。

409 冲突，410 失效，503 存储不可用。新 scope 只从页面原文重建，不继承旧 selections 或重跑旧工具；状态未知不自动重建。审批仍断线取消。转普通聊天／导出保留原始调用、冻结引用和 native 签名，去掉临时派生身份，保存失败保留原页面。

临时缓存不写普通聊天或四张 V2 SQL 表，也不表示永不落盘：Redis AOF/RDB/副本/备份由部署策略控制；不自动修改全局持久化设置，不引入额外页面密钥协议。
