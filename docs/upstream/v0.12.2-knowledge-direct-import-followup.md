# v0.12.2 知识库直接导入后续决策

## 基线与目标

- 日期：2026-10-21。
- 起始版本：`d9a49acba6129b67d496f35c75ce83a29884173f`。
- 扩展[知识库写入工具](v0.12.2-knowledge-write-followup.md)，保留原有文本创建及编辑接口。

新增 `import_knowledge_url` 和 `import_knowledge_terminal_file`，让模型只提交来源与目标，
由后端获取、解析、保存并关联文档。源文件及全文不进入工具返回值、引用上下文或模型续接请求，
因此导入不受模型上下文容量限制；仍受部署的文件大小、格式、解析服务及服务器资源限制。

## 范围与授权

一次调用同步导入一个来源。网页保存配置加载器提取的正文；文件链接和终端文档保留原始上传字节，
复用已有解析器、分块和嵌入流程。没有新增依赖、公共 HTTP 接口、数据库迁移或独立开关。
不包含网站递归抓取、目录批量导入、个人直连终端、后台任务或文件覆盖。

沿用显式 `knowledge_write=true`、读取依赖、模型内置工具权限、挂载范围及执行时资源 ACL。
已知 URL 的直接导入不要求网页搜索开关；URL 仍受现有网络安全和域名策略约束，不能携带 WebUI
登录凭据访问目标站点，也不能借导入绕过文件类型或大小限制。不能应用面向模型的 `fetch_url` 截断。

来源记录不保留 URL 查询参数、片段或终端认证信息。网页自动文件名沿用现有字符替换、大小写和
长度规则，但使用去掉查询参数与片段后的 URL，避免临时下载凭据经文件名进入共享知识库。

基础网页加载器解析已限量下载的 HTML，不再发起第二次无上限下载。浏览器及外部网页加载器
继续遵循各自的运行环境和服务限制，最终提取文本另行校验大小；不能把直接下载上限解释为
这些加载器整体内存、子资源或远程服务的总开销上限。

终端来源只绑定请求当前选中的管理员连接，并检查模型终端能力。身份、认证及聊天／自动化上下文
来自服务端；通过固定文件接口读取规范化绝对路径，不在 WebUI 主机打开该路径，不接受模型指定
其他终端、用户或会话，也不跟随终端响应重定向。保留既有签名下载、同源文件隔离和访问撤销规则。

## 保存、取消与重放

来源获取与外部处理不持有数据库事务。获取前、保存和关联前重新核实相关权限。
根目录名称冲突必须明确返回；不覆盖、不自动改名，也不把截断的来源当成完整导入。

成功需要核实处理状态和真实知识库关联。启用检索绕过时，明确返回未建立索引且按配置跳过。
清理仅涉及本次创建且确认未关联的孤立文件；保留文件返回文件 ID 及实际保存／关联／索引状态，
供调用者核实后恢复。关联前失败时按本次文件 ID 清理目标库中的孤立索引，不按内容哈希删除其他文件。
孤立文件删除在 SQL 操作中复核所有知识库关联，保留并发关联已成功的文件；清理无法确认时明确
返回 `cleanup_verified: false` 和 `file_retained` 状态，不能将数据库记录已删除等同于物理清理已完成。
只有取得孤立文件删除权后才清理其索引；关联插入也在 SQL 操作中要求文件仍存在，避免清理先
完成时出现悬空关联。PostgreSQL 下两条路径先锁定同一文件行，再执行条件语句，使等待后的
语句能看到已提交的关联或删除结果；锁内不执行外部 IO。
取消时先收敛已启动的阻塞持久化工作，避免清理与解析、索引并发操作。
审批恢复及模型传输重试继续使用现有已完成结果，不重复执行导入。

## 验证记录

- 使用 Python 3.12.15，数据库、静态目录及本地 HTTP 来源均隔离，测试数据为合成内容。
- 首次独立审查前，知识库、终端、工具审批、重放和原生协议相关的 17 个测试文件共
  **597 项通过**，有 1 条既有 Starlette/httpx 弃用警告。
- 独立审查发现基础 HTML 加载器重复下载，以及孤立索引清理与并发关联的竞争问题。
  已通过失败测试复现并修复，同时覆盖清理先完成时的反向竞争，复审通过。
- 最终代码上的 8 个受影响测试文件共 **207 项通过，无警告**，包含原有写入、导入、
  SQLite／HTTP 集成，以及四种原生协议在 off／legacy／V2 下的结果隔离和重试检查。
- 集成场景使用真实文本、PDF 和 Word 解析器；向量及嵌入使用确定性替身。
  16 个 Python 文件通过 Ruff 格式及 CI F 类检查，文档通过 Prettier、相对链接及
  `git diff --check` 检查。

未运行全量后端测试、前端构建、真实模型／生产终端联调或 PostgreSQL 运行时验证。
PostgreSQL 行锁部分经过代码复审，SQLite 集成测试不能代替 PostgreSQL 运行时验证。
这些结果也不代表已验证部署配置的浏览器或外部解析服务。
