## 问题与相对上游的差异

在启用自动上下文时，DeepSeek 思考模式可能在新聊天的首次提问就拒绝请求，提示缺少
`reasoning_content`，即使模型配置已开启推理回传。自动加载的上下文本来不是模型生成的回复，
没有对应的上游推理。回传开关负责保留实际收到的推理，不能为合成调用创造原始值。

DeepSeek 的[思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode#tool-calls)要求工具请求
保留实际推理；[工具调用文档](https://api-docs.deepseek.com/guides/tool_calls#inserting-tool-calls-mid-conversation)
说明 Chat Completions 不支持客户端插入的非模型工具调用，而 Responses/Anthropic 接口具有不同支持范围。

固定官方 v0.13.3 的实际实现：

- [`hidden_tool_result` / `preload_memory`](https://github.com/open-webui/open-webui/blob/b0e6098e940942281d9c83f3529ea117287a3a22/backend/open_webui/utils/middleware.py#L3053)
  把自动上下文表示为隐藏的普通调用和结果；初始化阶段通过
  [`initial_output`](https://github.com/open-webui/open-webui/blob/b0e6098e940942281d9c83f3529ea117287a3a22/backend/open_webui/utils/middleware.py#L3005)
  进入工具历史。工具启用时的技能清单和挂载知识清单也使用此路径。
- [`get_reasoning_format`](https://github.com/open-webui/open-webui/blob/b0e6098e940942281d9c83f3529ea117287a3a22/backend/open_webui/utils/middleware.py#L1886)
  区分 Ollama/llama.cpp；普通兼容模型没有本 fork 已有的精确原始推理回传策略。
- [`convert_output_to_messages`](https://github.com/open-webui/open-webui/blob/b0e6098e940942281d9c83f3529ea117287a3a22/backend/open_webui/utils/misc.py#L490)
  在 `reasoning_content` 格式下会为缺少推理文本的工具轮补入空字段；这不是自动上下文的原始推理。

fork 的 D04 已经把自动私人/运行时上下文放在请求内并冻结，避免写入普通输出和共享摘要。
此前传输仍将这些内部调用/结果对发给 Chat Completions。**本次增量是传输表示的分离**：保留内部
冻结身份及权限来源，服务端 Chat Completions 在发出请求前将其投影成系统上下文。

## 已采用的技术选择

| 选择                       | 实际实现与理由                                                                                                                                                            |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 按协议处理，而非猜测模型   | 仅作用于服务端 Chat Completions；不按 DeepSeek 名称、连接 URL 或工具名称启用。Responses、原生 Gemini/Anthropic 保留既有表示，不新增配置开关或协议推断。                   |
| 只接受服务端来源身份       | 使用 `request.state.private_tool_context` 的调用 ID 识别自动上下文；客户端 metadata、同名工具或 `hidden` 标志不能授予此身份。                                             |
| 投影副本，保留内部快照     | 内部调用/结果对继续用于请求私有隔离、审批冻结匹配和 legacy 摘要排除；不改写保存的输出、原始结果或已执行工具。过滤器对本轮输入的合法改写仍保留。                           |
| 系统上下文与原始推理分开   | 自动内容附带来源名称/参数，保留正文空白与缓存块；真实 assistant 调用、`reasoning_content`、`reasoning_details` 和签名继续按原合同回放。推理回传开关不控制自动上下文投影。 |
| 先规范化，再转换角色和计数 | 合并为唯一的开头 system 消息，随后沿用 OpenAI 模型的角色转换，再执行最终预算。无主动过滤器改写时，相同冻结来源在续轮保持同一前缀；V2 将其计为固定输入，不当作新工具结果。 |
| 保持工具配对和续写边界     | 混合批次移除自动调用后，真实调用与结果仍配对。去除仅为 llama.cpp 转换生成的空 assistant/空推理载体，避免错误触发 Continue prefill；保留真实文本和推理/签名。              |

不采用以下替代方案：

- 给每条 assistant 补 `reasoning_content=""`：不能恢复原始推理，也未解决 Chat Completions 对合成调用的限制，
  还会掩盖真实推理丢失或留下空的续写载体。
- 要求关闭思考或取消技能、记忆、终端：会改变用户选用的能力，不能修复传输表示。
- 为某个模型名或域名单独分支：不能覆盖同协议的自定义连接，也使兼容行为依赖命名。
- 改写历史、把自动上下文登记成新工具结果或重新执行工具：破坏来源、隐私、固定选用和幂等边界。

无数据库迁移、依赖变更或新配置默认值。原来的推理回传开关仍默认开启；旧历史中已丢失的上游推理
不会被这次修复恢复。此变更不等于所有供应商的在线兼容性或缓存命中保证。

## 实现与验证

实现入口为 [`project_private_tool_context`](../../backend/open_webui/utils/openai_compatibility.py) 和
[OpenAI 兼容发送路由](../../backend/open_webui/routers/openai.py)。当前约束在
[根 AGENTS](../../AGENTS.md#tool-continuation-prompts-and-gemini-signatures)及
[后端 AGENTS](../../backend/AGENTS.md#input-cache-compatibility)，用户说明在
[README](../../README.md#功能与设计决策差异--behavior-and-design-differences)和
[兼容指南](../gemini-cache-replay.md#openai-兼容参数与续轮--openai-compatible-requests)。

[新增回归套件](../../backend/tests/test_private_context_transport.py)共 12 项，覆盖首次请求、开关两态、
原始推理与续轮前缀、审批快照重新投影、来源隔离、过滤器与缓存块、混合批次、其他协议、OpenAI 角色
转换及 llama.cpp 空载体。测试先复现缺陷，再验证修复；独立审查提出的规范化和空载体问题均补有回归。

2026-11-17 在 Python 3.12.14、独立 data/static/SQLite 和合成测试密钥下，30 组相关套件共
**970 项测试与 26 个子测试通过**。Ruff 格式/CI 逻辑检查、文档 Prettier 和 `git diff --check` 通过。
初次组合运行有三项因隔离环境缺少测试密钥中断，补齐合成环境后完整重跑通过；未修改真实部署密钥。
现存依赖弃用警告不影响通过结果。

交付前补充文档后，自动上下文、精确推理回传和 v0.13.3 工具上下文三组聚焦套件再次运行，
**41 项通过**；本阶段未修改已通过组合验证的运行代码。

命令统一在 [DEVELOPMENT](../DEVELOPMENT.md#input-cache-compatibility-verification)，传输改动需结合
[Gemini 回放检查](../DEVELOPMENT.md#gemini-cache-replay-verification)。这些模拟边界测试不等于
完整后端/前端验收、生产构建、部署或真实 DeepSeek API 验证；本次未执行这些检查。
