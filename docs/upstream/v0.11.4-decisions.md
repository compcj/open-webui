## 产品决策

每个编号在本文件中保持稳定。分类区分采用上游、保留差异和适配接口；未来版本引用本记录，
在新版本记录中说明保留或替代原因，不修改这里的历史理由。各项实现状态以末尾验收记录为准。

### D01 — 完整合并（采用上游）

上游提供完整 v0.11.4 发布；本分支此前基于官方 v0.11.3 并叠加自有能力。本次采用真实双亲合并，
而非选择性移植提交。这样保留上游历史与后续合并关系，代价是需要验证非冲突文件及依赖变化。
不恢复分支删除的 PyPI/Docker Hub 发布流程，不自动推送或发布。

证据：Git 双亲与祖先检查、依赖锁一致性、前后端测试及构建。下次升级继续核对官方 SHA；
只有明确改变维护策略时才改为选择性移植，不能为了减少冲突而伪造合并历史。

### D02 — 工作区技能白名单（保留差异、适配接口）

上游原生工具可以自动发现用户可访问的活动技能；旧分支主要使用显式选择、提及和模型预设。
本次自动发现要求全局白名单与原有访问权限同时满足，对管理员也适用；默认空白名单。
手动选择和模型预设保持原有语义。白名单是发现策略，不授予资源访问权。

管理员使用 `GET/POST /api/v1/configs/skills`，字段 `AUTO_DISCOVERY_SKILL_IDS: string[]`，
持久化键 `skills.auto_discovery.ids`，默认 `[]`。设置不进入可分享的技能元数据。
替代方案是自动公开所有可访问技能；未采用的原因是新增技能不应自动改变现有聊天的工具上下文。
代价是管理员需维护清单。

实现边界：[配置路由](../../backend/open_webui/routers/configs.py)、
[聊天注入](../../backend/open_webui/utils/middleware.py)、
[技能加载](../../backend/open_webui/tools/builtin.py)、
[发现策略回归](../../backend/tests/test_skill_discovery_policy.py)。验收覆盖空值、非管理员写入拒绝、权限交集、
管理员同样受限、显式选择和预设。当上游提供等价的发现策略及默认值时才考虑收敛。

### D03 — 按终端授权自动发现（保留差异、适配接口）

上游从所选终端获取技能列表。分支采用管理员保存的连接级
`config.auto_discover_skills: boolean`，默认 `false`；开启后该连接现有及以后新增的技能均可自动发现。
不使用客户端提交的连接元数据授予自动发现权限，个人直连终端不会因此获得授权；手动技能使用保留。
替代方案是逐技能白名单；选择连接级策略是为了允许受管理终端独立维护其技能集合，代价是管理员
必须信任该终端后续新增的技能。

终端技能使用 `terminal:` 命名空间，切换终端清理发现状态；OpenClaw 文件仅在实际加载时准备，
清单生成不批量同步未使用技能。加载失败降级，依赖安装仍须显式触发。
证据：[终端配置](../../backend/open_webui/routers/configs.py)、
[运行时](../../backend/open_webui/utils/skills_runtime.py)、
[输入区集成](../../src/lib/components/chat/MessageInput/IntegrationsMenu.svelte)、
[发现状态回归](../../src/lib/utils/skill-discovery.test.ts)。
未来须复查授权来源、缓存隔离、新增技能和失败降级，而不能只比较字段是否仍存在。

### D04 — 每轮读取 AGENTS.md（采用上游）

旧分支没有这项统一自动加载；本次采用上游每轮读取所选终端 home 中 AGENTS.md 的行为，
与技能白名单分开。文件缺失、不支持或超时不阻断聊天。替代方案是随技能授权一起关闭；未采用，
因为用户已选择将终端工作说明作为独立上下文来源。代价是终端文件修改可影响下一轮聊天。

证据：[终端上下文](../../backend/open_webui/utils/terminals.py)、
[聊天注入](../../backend/open_webui/utils/middleware.py)。保留上游的读取时限和大小限制；
未来复查读取目录、每轮刷新及异常处理，不能将文件内容当成服务端授权策略。

合并验收发现 AGENTS.md 的合成用户消息会干扰按用户轮次配对附件；现先为真实用户消息补全文件上下文，
再插入 AGENTS.md。[组合回归](../../backend/tests/test_terminal_agents_attachments.py) 覆盖持久/临时聊天、
图像上下文及关闭内置工具后的每轮加载。未来升级必须同时检查这两个注入阶段的顺序。

### D05 — 摘要也可以编号引用（保留差异）

上游 v0.11.4 移除了 `search_web` 的这条来源转换路径；分支保留搜索摘要及抓取正文的可引用证据。
最终区分 `search_snippet`、`search_result`、`page_excerpt`。无摘要的搜索结果仅作导航，
详细事实和直接引文仍要求模型抓取正文；系统不把摘要宣称为已阅读的原文。
替代方案是只有正文可编号引用；保留摘要引用以兼容现有检索工作流，代价是需要明确展示证据层级。

保留跨工具、文件及后续轮次的稳定编号，同时采用上游可配置的来源元数据筛选；属性、正文须转义，
链接须校验协议。证据：[引用测试](../../backend/tests/test_web_tool_citations.py)、
[网页工具测试](../../backend/tests/test_builtin_web_tools.py)。未来如上游恢复等价来源契约，
以混合来源、无摘要、抓取失败和恶意元数据测试判断是否可以收敛。

### D06 — 保留输入区布局（保留差异、采用部分上游交互）

保留分支输入区布局、推理强度和工具控制项及记忆偏好，接入上游终端技能、创建技能入口和后续提问建议。
不整体替换为上游布局，避免破坏窄屏操作和现有使用习惯；代价是后续合并仍需维护组件差异。

用户设置按变化字段保存，省略保留、显式 `null` 重置，嵌套映射仍整体替换。
保留保存队列、账号切换和错误反馈。证据：[输入区](../../src/lib/components/chat/MessageInput.svelte)、
[聊天](../../src/lib/components/chat/Chat.svelte)、
[偏好测试](../../src/lib/utils/tool-feature-preferences.test.ts)、
[设置真实处理器测试](../../src/lib/components/chat/SettingsModal.test.ts)、
[输入法/Tab 测试](../../src/lib/components/common/RichTextInput/AutoCompletion.test.ts)。验收包括旧页面不覆盖无关设置、
连续相反操作、Tab、中文输入法和窄屏。保存失败的字段保留待确认状态，重试同值仍发请求；较早失败不得覆盖
后来排队的选择。模型列表刷新完成后再次检查账号和 token，防止旧账号结果写入新账号。
未来只有交互及数据兼容均等价时才移除分支实现。

### D07 — 默认隐藏个人直连配置入口（采用上游）

采用上游 `direct.integrations.enable` 默认关闭的入口策略，管理员可开启；已有连接继续可用。
它与模型直连 `direct.enable`、分支聊天访问开关 `chat.direct_api.enable` 不同。
替代方案是维持入口始终可见；选择上游默认值以控制新连接配置入口，同时避免使已有连接失效。
这是界面策略，不替代后端工具权限和网络信任边界。

证据：[连接配置](../../backend/open_webui/routers/configs.py)、
[个人设置](../../src/lib/components/chat/SettingsModal.svelte)。未来升级须测试入口关闭时已有连接仍可使用，
并检查这三个独立开关是否被误合并。

### D08 — 保留终端文件隔离（保留差异）

上游存在终端端口预览链路；分支继续拒绝同源端口代理，保留绑定用户、终端和聊天/自动化上下文的
签名文件链接、受限静态预览和 SVG 安全响应头。替代方案是直接启用上游预览；未采用，
因为终端内容不应获得 WebUI 同源执行能力。代价是不能在聊天中直接使用交互式端口应用。

合并上游管理路径拦截、重定向拒绝、退出后断开和周期性权限复查；Cookie 转发须显式开启。
证据：[终端路由](../../backend/open_webui/routers/terminals.py)、
[文件测试](../../backend/tests/test_terminal_file_routes.py)、
[真实 WebSocket 测试](../../backend/tests/test_terminal_websocket.py)。
未来只有在等价隔离的预览架构下才能重新考虑端口预览；不能用用户记住的设置解除隔离。

### D09 — Redis 撤销检查故障时拒绝（保留差异）

上游在 Redis 错误时接受令牌以保持可用性；分支选择无法验证撤销状态时拒绝请求。
HTTP 返回 `503` 和重试提示，终端 WebSocket 使用 `1013`；有效登录 Cookie 不因短暂故障被删除。
未配置 Redis 的部署维持现有行为，已撤销或无效凭证正常拒绝。
替代方案是故障时继续放行；选择拒绝以避免已撤销会话重新生效，代价是 Redis 故障影响需要校验的会话。

证据：[认证实现](../../backend/open_webui/utils/auth.py)、
[故障回归](../../backend/tests/test_auth_revocation.py)。未来升级必须复查所有 HTTP/WS 调用方和异常转换，
同时测试故障恢复；不能把不可用错误改成无效密码，也不能静默绕过。

### D10 — 标准镜像为主要支持目标（采用上游边界）

采用上游 v0.11.4 slim 的精简边界：外部 AI 服务、SQLite/PostgreSQL 应用数据、pgvector 和本地文件存储。
标准镜像为本分支主要验证目标；不承诺 slim 支持本地模型、音频/文档处理、浏览器或其他存储/数据库后端。
替代方案是补齐 slim 中所有标准镜像依赖；未采用，因为会消除其体积和运维定位。

证据：[Dockerfile](../../Dockerfile)、[slim 依赖](../../backend/requirements-slim.txt)。
未来升级同时检查默认镜像、构建参数和插件实际依赖，不能仅因 import 可选就声称功能等价。

## 升级与回滚

1. 在测试环境克隆生产数据，备份数据库、上传文件、配置及当前镜像标识；保持测试服务与生产存储隔离。
2. 检查外部 Tools/Functions 自己声明的依赖。上游减少了隐式安装的软件包，例如 `langchain-community`；
   插件不能再依赖镜像偶然附带这些包。核对图像验证调用方的 POST 契约。
   前端锁文件通过 `npm ci` 安装；Python 锁通过 `uv lock --check --python 3.11` 核对。
   构建脚本从 PyPI 获取纯 Python 轮子；本次生成的 Pyodide 锁相对上游仅将 Black 更新为 26.10.0，
   已核对全部 7 个下载轮子的 SHA256。后续构建仍需检查生成差异，不能假定该步骤完全固定版本。
3. 初次升级工作区自动发现白名单为空，终端自动发现关闭；个人直连配置入口默认隐藏；Cookie 转发默认关闭。
   管理员按 D02/D03 授权后再验证聊天，不批量改变手动选择和预设。
4. 官方 v0.11.3 到 v0.11.4 没有新增 Alembic 修订；本次配置使用现有配置存储，不新增业务表。
   这不免除克隆数据启动验证。检查既有 PostgreSQL 向量索引和 pgvector 版本；是否重建单独评估，不自动重建。
5. 使用标准镜像核验上传、Tika、检索、工具、长流式回复、停止/恢复和终端访问。验证后再由部署负责人执行上线。
6. 回滚时恢复匹配的旧镜像、数据库和文件备份，勿假定旧代码可以安全读取所有后续写入。
