## 决策与兼容性

管理员在网络搜索设置选择 Search1API 后，使用 `/search`、`/ask` 下拉框指定全局接口。
沿用现有提供商设置和共享搜索入口，使聊天内置搜索与自动联网检索行为一致。
默认保持 `/search`，避免升级后隐式改变搜索方式和服务消耗；不增加会话或工具调用参数。

`SEARCH1API_ENDPOINT` 环境默认值为 `search`，持久化键为
`web.search.search1api_endpoint`，管理员配置 API 字段为 `web.SEARCH1API_ENDPOINT`。
接受的值只有 `search` 和 `ask`。启用持久化时已保存值优先；更新请求省略字段或传入
`null` 保留原值，非法值返回 422。旧安装通过配置默认值兼容，无需新迁移。

两个接口继续使用现有服务地址、Bearer 密钥与会话池。`/search` 请求保留
`query`、`max_results`；`/ask` 只发送原始 `query`。规范化结果后保持既有结果结构，
先执行域名过滤，再应用本地数量限制；不改变引用证据和编号规则。
非法运行时接口配置在网络访问前报错，HTTP 错误不触发自动回退或额外请求。

官方 `/ask` 通过自然语言查询选择搜索源并排序，最多返回十条搜索结果，查询最长
500 字符，不生成最终回答。成功响应中的部分搜索源错误不丢弃其他已返回结果。
查询不自动截断，服务端错误沿用原错误链路。能力、限制和费用以
[官方文档](https://s1.dev/docs/basic/ask)为准。
