# v0.13.3 input-cache compatibility follow-up

Recorded on 2026-11-12 against `ba257fc6c024d14142d8d187f1d30dfda148d72e`, after the
[Gemini prompt/signature fix](v0.13.3-gemini-cache-followup.md). This record covers request shaping and

## Explicit design decisions

The user selected per-model `reasoning_content_replay`, default on. Store the exact upstream field
separately from displayed reasoning and replay only that field; disable replay without disabling
`reasoning_details`. Old unmarked display items and other reasoning aliases cannot establish its value.
No database migration is required; original outputs and model-switch projections remain independent.
Raw reasoning retains each code continuation's response boundary. Signed message reordering records
its message-ID association so early/late reasoning and opaque details replay with the same text and
calls. Invalidated projection IDs prevent later code rounds from restoring another model's carriers.

Request filters remain active every round and may intentionally rewrite the prefix. Capture a detached,
unfiltered baseline after private context preparation, then use fresh copies for each continuation.
Resolve each selected model's configured prompt once per request and apply the frozen text after the
filter. Nonempty filters already use eager legacy compaction; moving the final initial filter after
private-context insertion does not move a routed request behind a previously deferred compaction step.
Legacy tool thresholds retain prepared system-text accounting; final V2 guards inspect filtered input.
Approval preflight remains before effects, and approval requests retain their existing new-request
preparation boundary. Stateful Responses still cannot rewrite provider-held history.
Approval preflight detaches the entire body, including tool schemas and nested provider options;
filter denial cannot contaminate the later canonical baseline.

Final stops retain tool definitions, set `tool_choice=none`, and append the instruction as a user
message. Backend execution guards remain authoritative if the provider ignores that choice.

`extra_body_compatibility` is an explicit default-off model switch. Enabled expansion requires an
object, occurs once before final budgeting and native internal-marker cleanup, and gives explicit
top-level parameters precedence (including false/empty values). Nested metadata is not a source of
request identity. Disabled mode retains existing nested wire semantics. Known cache/routing strings
avoid generic JSON coercion; other JSON parameters, reasoning-effort literals and Ollama remain unchanged.

## Deterministic fixes

System normalization retains all content blocks and cache annotations. Injection adds one text block
without rewriting cached blocks. Image and Chat/Responses conversion retain supported supplied markers.
Subagent schema descriptions follow deduplicated configured model IDs with unchanged access filtering.
Cache-read aliases normalize to one canonical counter before round accumulation; analytics reads
surviving historical DeepSeek counters last in the fallback order. Missing is distinct from zero;
lost historical totals cannot be reconstructed. Latest-call prompt usage remains available to compaction.
