## 真实服务与浏览器

真实 Redis 已验证票据跨 store 读取、过期、撤权及不可用时拒绝，使用随机测试前缀，只清理自己的键。
实际 aiohttp WebSocket 重定向检查、FastAPI/ASGI 预览入口、SSE 跨 chunk 脱敏与中途撤权也已有通过证据。
最终标准镜像已用独立数据卷、两个 Redis worker 启动，没有源码 bind mount；225 个变更 Python 文件
与镜像内文件逐字节 SHA-256 比较一致。浏览器验证直接访问该镜像的打包前端。

| 本机真实链路                                                         | 已观察结果                                                                                                                                                       |
| -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 独立 Edge iframe → 预览 Host → 真实 Open Terminal → 终端内 HTTP 服务 | HTML/CSS、fetch、SSE、表单 POST、导航与带 `vite-hmr` 子协议的 WebSocket 通过                                                                                     |
| 实际 Browser 标签页                                                  | 修复等价连接对象重建造成的反复授权/iframe 重置后，资源、CSS、fetch、SSE、HMR、导航和表单通过；等候一分钟后续期保留当前页面，复用同一可见会话，关闭标签删除该会话 |
| 沙箱与退出撤权                                                       | DOM Cookie/localStorage 抛出 SecurityError，document.referrer 为空；退出后活动 HMR WebSocket 关闭，原票据 HTTP 被拒绝                                            |
| Host/来源/票据                                                       | 预览 Host 的 API、登录和 Socket.IO 均 404；主站拒绝预览和 null Origin；另一登录会话、另一上下文及伪造票据被拒绝；无缓存、无 Set-Cookie、严格 CSP                 |
| 禁用入口                                                             | 新票据被拒绝；旧预览 hostname 仍不能访问主站，恢复测试配置后继续使用                                                                                             |
| Tether                                                               | 禁用握手拒绝；Direct Integrations 关闭时独立发现并通过真实 WS 二进制 relay 调用终端 HTTP；禁用后通道关闭、发现消失                                               |
| 原生 Agent                                                           | 真实 Open Terminal 启动合成 JSONL Agent：发现、正常回复持久化和完成、忽略温和中断的真实进程强制停止通过；已收内容保留并标记不完整，私有原始帧不出现在公开历史    |

Agent 程序是本地合成协议 fixture，不调用外部模型；Tether 设备是本地合成协议客户端，流量确实经过
真实 WebSocket、两个应用 worker、Redis 和真实终端。故障矩阵中的 worker 丢失、404、丢失确认、
耐久停止意图、并行访问及容量边界另由上述完整测试覆盖，不能把它们都称为真实远端故障注入。

真实验证还发现 Open Terminal 0.17.7 / websockets 17.4 会为未指定子协议的 WS 发出空
`Sec-WebSocket-Protocol`；严格目标可能返回 400。带 `vite-hmr` 的链路通过，未放宽 WebUI 沙箱解决
终端依赖兼容性。终端重启后遗留的孤立预览进程也曾被 `/ports` 正确拒绝，fixture 在当前终端内重建后恢复。

未使用真实外部模型/编码 Agent 的账号或计费凭据。使用模拟供应商、ACL 双替身或合成 Agent 的结果将明确注明，
不会作为某个供应商账号实际可用的证明。预览内部 Cookie jar、WebSocket 重定向权限以及 Agent 强制
停止的尾部输出取舍已获用户确认，详见[决策记录](v0.13.3-decisions.md#实施期间确认的协议边界)。
