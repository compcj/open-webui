# Open WebUI v0.12.2 上游合并计划

本文件归档用户于 2026-10-15 批准实施的计划。实施结果和实际验收证据另见
[版本决策记录](../../upstream/v0.12.2-decisions.md)，此计划不代表已经完成验收。

## 1. 目标与已确认决策

完整合并官方 **v0.12.2**，包含 v0.12.1 的累计变更，应用版本更新为 **0.12.2**，同步维护说明、协作规则和升级文档。

已核验基线：

- 当前 `main`：`b671c64cba91ef31071c7c0da531b9bd96057c60`，工作区干净。
- 官方目标：`6a18585ff4c2e5f6805f682222cfbc46dc669ef8`。
- 共同祖先：官方 v0.12.0 `15818d88fd7bde1b73de33590f50d15d21e8d7c1`。
- 累计 **210 个提交、247 个变更文件**；隔离三方预演发现 **78 个冲突文件：14 个代码／工作流文件、64 个翻译文件**。上游功能范围见 [v0.12.1](https://github.com/open-webui/open-webui/releases/tag/v0.12.1) 和 [v0.12.2](https://github.com/open-webui/open-webui/releases/tag/v0.12.2)。

已按用户选择确定：

- **共享语音采用上游限制**：非所有者不能发起通话，切换到他人共享聊天时结束通话；保留旧转写的作者归属与隐私过滤。
- **技能采用上游概览策略**：启用技能工具时，超过 20000 字符的技能首载 5000 字符，通过搜索及分页继续读取；未启用技能工具时仍最多注入 100000 字符。
- 其余既有分支契约继续保留；新增 Apps 默认关闭，升级不主动开启 Tool Search、Realtime 或 V2。

## 2. 合并顺序与冲突处理

从上述分支 HEAD 建立隔离工作树，使用 `codex/merge-upstream-v0.12.2` 分支。按官方 SHA 合并，保留真实双亲历史，不依赖本地同名版本标签，不使用整文件批量选择 ours/theirs。

| 区域                 | 冲突与处理方案                                                                                                                                                                                                              |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 工具执行与供应商回放 | 合入 `call_tool(tool_name, params)` 分发机制。保存原始 `provider_function`，实际工具身份用于权限、审批、执行和结果分类；供应商回放恢复封装调用。保留 Gemini 原始参数校验、跨轮调用 ID 规则、确定性拆分和重试不重复执行。    |
| 引用与压缩           | 在现有统一引用处理入口兼容上游审批来源修复、外部知识标题及链接修复，避免重复事件。保留冻结引用文本及稳定前缀。Legacy 接入上游轮间检查点和单轮 usage；off/V2 不执行 Legacy 截断，V2 继续核算完整最终请求。                   |
| 技能与终端运行       | 合并概览、`grep_skill_files`、`.skill` 导入导出及归档修复。概览、搜索和分页使用同一固定版本与运行时准备后的正文，确保 `{baseDir}` 替换后的偏移一致。保留发现白名单、连接 opt-in、ACL、软失败、`data.files` 和乐观版本校验。 |
| 技能精确结果预算     | 为服务器注册的技能搜索增加精确结果处理，按完整匹配条目缩减并明确标记遗漏，不进行语义摘要。保留分页所需的绝对偏移；外部同名工具不能获得可信内置工具身份。                                                                    |
| 语音                 | 合入 Azure Realtime、普通通话头像、唤醒锁和音频资源释放修复。前端限制与后端通话／新转写入口同步检查所有权，保留模型权限、持续撤权检查及 Redis 故障时的可重试拒绝。旧消息继续使用作者隐私规则。普通语音听写不扩大限制。      |
| 聊天与编辑界面       | 接入修订比较、Keep both、多模型消息对、草稿工具选择和评分保留修复。保留模型控件优先级、Gemini 配置、模型访问授权、增量设置保存、思考状态和流式错误恢复。比较结果应用前检查草稿及版本未变化。                                |

- 保留上游两条迁移：`c92da83b017f` 增加 Apps 数据结构，`0bd252b206fb` 补齐缺失 auth 行。

## 5. 验证与交付标准

先使用 **Node 22、Python 3.11/3.12** 在当前 HEAD 建立基线。当前默认 Node 20、Python 3.14 不作为正式验收环境。

必须覆盖：

- **工具链**：严格供应商下的搜索→分发→审批→执行→刷新回放；非法参数、同名外部工具、跨轮重复 ID、拆分调用、取消及重试；引用不重复，Gemini 校验与 V2 预算不被绕过。
- **压缩与技能**：三种模式隔离；Legacy 检查点重载；V2 已选历史稳定；概览边界、中文偏移、搜索遗漏、固定版本、OpenClaw 运行时正文、自动发现关闭、终端故障及 `.skill` 往返。
- **权限与界面**：所有者可通话，非所有者及非所有者管理员不能绕过；旧转写隐私、撤权和 Redis 故障保持正确；比较编辑并发保护、模型控件、草稿、评分、窄屏和中文输入法。
- **迁移**：空库、现有分支 0.12.0、官方 0.12.0／0.12.2 数据库升级到唯一 head；验证 Apps 约束、auth 补齐、旧数据不变及重复升级。SQLite 和临时 PostgreSQL 分别验收，DDL 编译不能替代 PostgreSQL 执行。
- **整体检查**：运行完整前后端测试、`npm run check`、`npm run build`、`uv lock --check`、发布脚本测试和工作流检查；按改动文件运行 Prettier、Ruff、文档链接检查及 `git diff --check`。类型诊断按文件和内容与基线比较，不只比较数量。
- **运行验收**：隔离数据库、数据和静态目录启动完整应用，检查版本、登录、聊天及标准容器启动。真实模型、Azure、Redis、终端等未实际执行的验证单独列出，不用模拟测试代替。

交付包括真实合并历史、0.12.2 版本、更新后的文档、冲突处理记录和验收报告。回滚说明采用升级前数据库、上传、配置及镜像整套备份，并注明 Apps 消息可能阻止降级。

本次范围为规划及后续本地整合；推送 `main` 会触发版本发布流程，发布与部署须按另行授权执行。计划批准时已完成远端 SHA 核验、隔离合并预演、迁移图静态检查和工作区检查，尚未执行应用测试或修改仓库文件。
