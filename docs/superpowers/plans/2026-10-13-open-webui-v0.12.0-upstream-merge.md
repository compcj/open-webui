# 合并 Open WebUI v0.12.0 的实施计划

## 1. 目标与已确认决策

从当前 `main`（`6e9b2f932c252be19235fd7694f7359064f9e239`）完整合并官方 v0.12.0（`15818d88fd7bde1b73de33590f50d15d21e8d7c1`），保留真实 Git 合并关系，并完成代码、数据兼容、回归验证及文档更新。

| 设计项        | 已确认方案                                                                                 |
| ------------- | ------------------------------------------------------------------------------------------ |
| 上下文压缩    | legacy 升级为上游 v0.12 行为；V2 完整保留并独立调度；升级不自动开启 V2。                   |
| 推理控件      | 普通模型统一到上游模型控件，兼容旧配置和记忆；不支持上游控件的场景保留原入口。             |
| 参数优先级    | 显式控件选择优先；选择默认时，先使用会话／个人高级参数，再回退到模型默认。                 |
| 多文件技能    | 统一使用上游 `data.files`，迁移旧 OpenClaw 文件并保留其运行能力。                          |
| 技能 URL 导入 | 采用上游网络安全限制；保留管理员及 `skills_import` 授权用户的导入权限。                    |
| 共享聊天      | 完整接入多人续写；工具执行、审批和停止操作按消息作者授权。                                 |
| 手动压缩      | 仅聊天所有者可以触发 `/compact`。                                                          |
| 共享 V2 状态  | 所有参与者共用同一聊天、模型、有效分支下的检查点和工具结果选用版本，不增加参与者隔离维度。 |

默认保留现有技能发现授权、终端文件隔离、Redis 撤销故障拒绝、引用冻结及原始历史保存契约。Tool Search、MFA 强制要求和 Realtime 通话采用上游默认，不在升级时主动开启。

## 2. 实施顺序与接口变化

### A. 建立隔离合并基线

- 在独立工作树创建 `codex/merge-upstream-v0.12.0`，开始前重新确认当前 HEAD、工作区状态、官方标签及共同祖先。
- 先记录当前分叉的测试、类型检查及构建基线，再执行真实双亲合并。
- 按功能解决冲突，同时检查没有文本冲突的相关文件；保留分叉发布流程边界，不恢复已删除的 PyPI、Docker Hub 发布步骤。

### B. 整合数据库迁移与技能体系

- 保留已有迁移，新增合并修订连接本地 `f9a4b2d6c805` 与上游 `b8f2c6d91a04`，随后添加兼容数据迁移。
- 将 OpenClaw 附件迁入 `data.files`，统一文本和 base64 文件表示；保留未知 frontmatter、source、config/env 等非秘密元数据。
- 文件树成为唯一编辑来源。旧格式通过适配器导入、读取和导出，避免两份文件内容分别更新。
- 保留旧正文，按现有序列化语义补齐 OpenClaw 的 `SKILL.md`；迁移不得静默截断、跳过文件或覆盖有效新版数据。发现无法转换的数据时，报告技能 ID／路径并停止该迁移事务。
- 接入上游技能版本历史和并发版本校验。恢复旧格式快照时经过兼容转换，生成兼容版本，不修改不可变的旧快照。
- 新文件更新使用 `expected_version_id`；过期更新返回版本冲突，缺失版本的旧附件编辑请求返回明确错误，要求刷新客户端。
- `/skills/load/url` 增加可选 `response_format`：默认保持旧下载描述对象，`packages` 返回上游解析后的技能列表；新前端使用 `packages`。两种模式共用下载校验、大小限制和解析器。
- 保留 GitHub、skills.sh、ClawHub、直接链接和多技能选择；采用上游下载及归档限制。终端同步、运行条件、`{baseDir}` 替换和显式依赖安装使用统一文件数据。

### C. 整合压缩、工具执行与引用

- 以全局模式分流：off 回放原始历史；legacy 使用 v0.12 轮间压缩；V2 使用现有最终发送预算与重试钩子。同一请求不得重复经过两套压缩算法。
- 采用上游并发审批、调用 ID 去重、暂停恢复、附件配对和 MCP 结构化结果修复；保留工具原文、调用／结果分组及已选定历史版本。
- 保留 `citation_context`／`citation_sources` 的冻结、持久化和原样回放。新来源随对应工具结果追加，不恢复上游重建前部 RAG 上下文的路径。
- 所有新增续调入口接入统一的计数、准备提交和发送流程；冲突及超窗重试不得重新执行工具。
- 接入默认关闭的 Tool Search。清单、实际工具定义和查询结果均计入完整请求预算。
- 为 `search_tools`、`view_skill`、`read_skill_file` 增加服务器识别的精确内容处理：工具定义保持完整条目，技能正文按精确分页缩小，不做语义摘要。连一个必要条目也无法容纳时返回可操作错误，不发送破损 schema。
- 保留 V2 的历史优先压缩、公平分配、原子选用、只读状态查询、摘要模型独立预算及通知归属规则。

### D. 接入共享聊天与权限继承

- 采用上游共享续写、消息作者、嵌套用户组及群组默认模型逻辑；每次执行仍校验当前用户的模型、工具和连接权限。
- 所有者的私人设置、聊天变量及凭证不自动交给其他参与者；参与者使用自己的授权上下文，审批和停止仅作用于自己的回复。
- V2 状态按用户选择共用；摘要输入限定为已保存的共享分支历史。个人系统指令、变量和终端运行上下文独立保留在当前请求中并计入预算。
- 为可共用的压缩记录增加服务器维护的来源标记。旧记录缺乏共享来源证明时保留原记录，进入共享场景后回放原文，不猜测其安全性。
- 共用状态继续使用来源校验和并发提交保护；其他参与者的后续请求不得重写已经选定的历史工具版本。
- 状态和原始工具结果读取统一采用聊天读取权限与分支校验；只克隆分享仅暴露分享快照。克隆不复制可直接复用的检查点、工具选用身份或原聊天游标。
- 手动压缩保持所有者权限；撤销共享或群组权限后，停止后续读取和实时更新。终端签名文件链接仍保留原用户与上下文绑定。

### E. 统一模型控件和前端状态

- 采用上游模型编辑器与控件组件，迁移旧推理档位、模型默认值、用户记忆及已保存聊天选择；任意自定义推理值映射为合法控件选项 ID。
- 已存在的新格式配置优先；旧字段仅作为兼容输入，迁移及保存后不再形成第二套可变配置。
- 确定有效值顺序：会话显式控件 → 用户记忆控件 → 会话高级参数 → 个人高级参数 → 控件／模型默认 → 全局默认。
- “默认／重置”必须真正清除显式选择，不能由旧记忆字段重新恢复；界面显示最终有效值。
- 保留直连等不支持上游控件场景的现有行为，以及 Responses 的 `reasoning.effort` 转换。
- 保留输入区布局、增量设置保存、连续操作排序、账号隔离、知识／记忆／笔记独立控制和中文输入法交互。

### F. 完成其余上游整合

- 接入 MFA、持久化会话撤销及实时连接复查，同时保留 Redis 故障时 HTTP 503／终端 WS 1013、有效 Cookie 不被删除的规则。
- 适配个人终端的浏览器读取路径、Windows 路径和提示词缓存选项；保持自动发现只信任管理员保存的连接授权，AGENTS.md 独立加载并软失败。
- Tavily 扩展为四种搜索深度，保留默认 `basic`、严格校验、遗漏／`null` 不覆盖旧值，以及搜索／提取深度独立。
- 保留 Search1API、命名图像引擎、生成／编辑配对、编辑禁用、图像上下文去重、ComfyUI 错误详情及 Tika JSON 协商。
- 合入其余上游功能和修复，包括 Realtime、知识文件浏览、资源版本历史和独立插件开关，并检查其与上述分叉边界的交叉调用。
- 使用包管理器更新并核验依赖锁；审查 Pyodide 生成变化。合并翻译后重新提取，确认再次生成不产生差异。

## 4. 验证与验收

使用 Node 22、Python 3.11／3.12，以及独立的数据、静态文件、数据库和 Redis 测试环境。

- **压缩与工具链：**覆盖三种模式、长工具链、并行结果、连续审批、暂停恢复、重复 call ID、Responses／Chat Completions、引用前缀、取消及超窗重试；断言没有重复执行、原文丢失或历史选用版本变化。
- **共享权限：**至少使用所有者、续写成员、只读成员、无权限用户四种身份；覆盖共用状态并发、个人上下文隔离、所有者手动压缩、作者审批、撤权、嵌套组和克隆。
- **技能与迁移：**覆盖原生／OpenClaw、文本／二进制附件、未知元数据、导入导出、版本恢复、并发编辑、URL 重定向及内网拒绝。验证新建库、当前分叉库和官方版本数据库升级，SQLite 与 PostgreSQL 均检查单一迁移末端。
- **控件与界面：**覆盖旧配置迁移、完整优先级、默认／重置、自定义档位、账号切换、刷新与导入导出、直连兼容，以及中文输入法、键盘操作和窄屏。
- **保留功能与新入口：**回归搜索、图像、Tika、终端隔离、Redis 故障恢复；执行 Realtime、Tool Search 和新增插件开关的定向集成检查。

实施时运行前后端完整测试、`npm run check`、`npm run build`、锁文件检查、Ruff、变更文件的 Prettier 检查和 `git diff --check`。检查实际测试收集数量，并验证 Markdown 链接及翻译生成幂等性。

类型检查按基线逐项归因，修复本次新增诊断及相关回归，不以错误总数下降作为通过证据。完整应用和标准镜像需在隔离环境启动验证；未执行的真实服务或容器检查明确记录为未验证。

## 5. 交付与升级边界

- 交付本地合并分支、完整文档、实际验证证据和遗留限制；最终确认两个真实父提交均在合并历史中。
- 标准镜像作为主要验收目标；slim 接入上游 S3 能力，不扩大其他未验证支持承诺。
- 升级前备份数据库、上传文件、配置和镜像标识；回滚使用匹配的整套备份，不假设旧代码可读取新数据。
- 本计划不包含推送、发布或生产部署，也不包含清理全仓库无关历史问题。
