### 阶段 B：完整临时聊天 V2

#### 架构与可信来源

- 复用现有 V2 算法，增加请求内的 `ContextScope`／`ContextStore`：保存聊天继续使用 SQL，临时聊天使用独立缓存。禁止通过全局变量切换 store。
- 服务端生成绑定当前用户的 `context_id、epoch、revision`；浏览器只保存在当前页面内存。socket 只负责投递，不能继续作为上下文身份。
- 同步带 `id、parentId` 的原始分支图，验证父链及来源修订。客户端不能提交可信 checkpoint、selection 或工具执行证明。
- 临时 store 同时支持原始快照、检查点、工具原文、候选／已采用版本、批次统计和执行记录。最终发送前仍执行完整预算校验及原子选用。
- 每个模型／分支／回复保持独立状态；支持现有 V2 已支持的传输。Pipe 继续排除，浏览器直连模型断线后不自动重发。

#### 新增接口

使用独立 `/api/v1/temporary-contexts` 路由，保持现有 saved-chat API 不变：

| 接口                                 | 用途                                         |
| ------------------------------------ | -------------------------------------------- |
| `POST /`                             | 创建临时 scope，返回身份、修订及期限         |
| `POST /{id}/sync`                    | 按预期 revision 同步原始分支或编辑           |
| `POST /{id}/lease`                   | 页面续租及认证后的 socket 重绑定             |
| `GET /{id}/state`                    | 同页重连后获取状态、任务及遗漏事件           |
| `POST /{id}/context-usage`           | 按模型／分支查询使用量，不采用新 selections  |
| `POST /{id}/compact`                 | 手动历史压缩；生成中拒绝，不采用工具候选版本 |
| `GET /{id}/tool-results/{result_id}` | 带身份、来源和分支校验的精确分页             |
| `DELETE /{id}`                       | 逻辑关闭、请求停止，确认完成后回收           |

现有生成请求新增 `temporary_context: {id, epoch, revision, branch_id}`。事件增加临时 scope、epoch、序号及回复身份，前端拒绝迟到事件。V2 已启用但旧客户端缺少必要身份时，明确提示刷新，不能悄悄绕过预算或运行 Legacy。

#### 缓存和失败行为

- 配置 Redis 时使用共享缓存及 CAS；未配置时仅支持单实例、单 worker 内存模式。Redis 故障返回 503，不切换到另一套状态。
- 默认：空闲 30 分钟、断线宽限 5 分钟、会话最长 24 小时，页面每分钟续租。容量为每上下文 64 MiB、每用户 128 MiB／最多 4 个上下文、每 store 512 MiB；允许通过服务端配置调整。
- 配额覆盖原文和派生数据，媒体使用既有授权引用。容量不足明确报错，不截断原文、不淘汰活动执行或已采用版本。
- 工具执行前记录 `started`，完成后记录 `resolved`；结果保存失败或执行状态不明记录 `uncertain`。这些状态不能因缓存缺失而触发重新执行。
- 409 表示修订冲突；410 表示已失效；503 表示存储故障。仅在旧 epoch 已隔离且确认无活动执行后，才允许从页面原文建立新上下文；旧工具结果作为历史重放。
- 显式离开先关闭并请求停止，清理等待执行者确认；真实关页采用最佳努力通知及服务端回收。过期本身不证明任务已经结束。
- 临时审批保持断线取消；不增加刷新后的历史或审批恢复。后台缓存沿用 Redis 部署持久化策略，文档不得宣称“永不落盘”。

#### 转为普通聊天与导出

先完成或确认停止当前回复，再保存完整原始历史。保留调用配对、`provider_function`、冻结引用和原生签名；去除临时上下文、checkpoint、selection、cursor 等派生身份。保存成功后释放临时 scope，失败则保留页面。JSON 导出采用同一投影。

## 5. 验证与交付标准

先以 Node 22、独立 Python 3.12 环境建立合并前基线；继续检查声明支持的 Python 3.11。默认 Node 20／Python 3.14 不作为正式验收环境。

- 产品选择：Integrations 前后端硬开关、管理员无旁路；无 Controls／Params 权限仍可用合法控件；技能 eager/lazy/mention 与发现授权独立；Access 即时生效、非法修改保留原授权；共享分支不夺取其他查看者的选择。
- 临时 V2：同 socket 新聊天、跨账号、同模型并发、分支／来源编辑、完整 C/B/T 预算、原文／图片／空结果、精确游标、状态、`/compact`；普通 chat 和四张 V2 SQL 表没有临时写入。
- 失败与执行安全：Redis 执行前后故障、CAS、超大结果、配额竞争、过期撞上长工具、停止超时、旧 epoch 写入、410 重建、503 不回退、审批及传输重试不重复工具。
- 既有合同：签名与供应商回放、引用前缀、知识写入权限和部分完成、多模型隔离、流中断保留、终端隔离、撤权失败及共享隐私。
- 基础设施：真实 Redis 多 worker、动态订阅／重连；MCP 超时／重定向／OAuth；SQLite 与实际 PostgreSQL 的空库、旧 fork、官方及当前数据库升级与幂等验证。
- 完整检查：前后端测试、`npm run check`、`npm run crypto:verify`、`npm run build`、`uv lock --check`、脚本测试、工作流检查、定向格式／链接检查、`git diff --check`。类型诊断逐文件对照基线；翻译按键合并，两次提取稳定。
- 运行验收：隔离数据启动完整应用及新标准容器；主要聊天、共享、工具、文件及临时 V2 流程。真实服务和模拟测试分开记录，缺失项目明确列出。

部署采用排空旧 worker 后协调切换：新 Redis reader 能读旧快照，旧 reader 不识别新格式，不未经验证宣称支持混合版本滚动升级。回滚使用升级前数据库、上传、配置及镜像整套备份。

交付为本地真实合并历史、临时 V2 实现、决策档案、更新文档和实际验收报告；不包含推送、发布、部署。
